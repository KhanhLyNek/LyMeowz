# ClientDev — source recovery workbench

This is an **experimental** Java ME client workbench for the existing
`LyMeowz.jar`, not a replacement for the shipped JAR.

## Source layout

- `../ClientSRC/src/` — initial CFR output, retained for forensic comparison
- `src/` — generated by CFR with duplicate-member renaming and experimental
  default-package normalization
- `../ClientSRC/resources/` — extracted JAR resources
- `reports/source-audit.md` — imports, source counts and common warnings
- `reports/protocol-analysis.md` — static I/O and command dispatch candidates
- `reports/compile.md` — summarized javac diagnostics
- `build.sh` — compile/build probe

## Java toolchain

Requires **Java 17+**, Bash, Python 3.8+, curl, and `jar`/`javac`.
The script downloads the **MicroEmulator 2.0.4** CLDC 1.1 and MIDP 2.0
API stub jars from Maven Central. These are compile-time API stubs, **not**
a working emulator or a complete J2ME device SDK.

```bash
bash ClientDev/build.sh
```

The script exits nonzero while recovered code does not compile. It does **not**
silently fall back to packaging the original `LyMeowz.jar`.

For an informative CI probe that retains a report on failure:

```bash
bash ClientDev/build.sh --probe
```

Run `.github/workflows/client-workbench.yml` to regenerate `src/` and
reports in the `client-src/workbench` branch.

## Expected limitations

1. CFR cannot recover original symbols, local variable names or comments.
2. The compiled JAR's default-package classes are referenced by
   `main.GameMidlet`. For easier source compilation we **experimentally**
   move the default-package Java classes into package `main` in `src/`.
   This changes JVM binary names and may break reflection/integration.
3. Javac success (if achieved) does not verify rendering, packet
   compatibility, networking, security or game behavior.
4. The reports deliberately do not publish decoded endpoints, secret
   strings, keys or account data.

Do not merge generated output to `main` without test results and permission
to use/redistribute the binary's underlying game resources.

## Decompiler recovery comparison (October 2026)

- **CFR 0.152**: 260 Java files, 58 invalid `** GOTO` markers; full source javac FAIL.
- **Vineflower 1.12.0 (default)**: 307 Java files, zero invalid `** GOTO` markers, but 297 out of the first 300 compiler errors concern duplicate symbols.
- **Procyon 0.6.0 (I1I1.java only)**: zero invalid `** GOTO` markers in the difficult class, yet its isolated compile produces many errors from obfuscated members and malformed expressions.
- **Input JAR classfile version**: all 351 classfile entries are 52.0 (Java 8), even though the JAR manifest declares MIDP 2.0 / CLDC 1.1.
- **Vineflower `--rename-members=1`**: separate experiment; see the workflow and `reports/vineflower-renamed.md` once generated.

Reports in `ClientDev/reports/`: `compile.md`, `source-audit.md`, `protocol-analysis.md`, `decompiler-comparison.md`, `procyon-target.md`, `I1I1-compile-comparison.md`, and `bytecode-inventory.md`.

Recovery candidates are deliberately kept in `ClientDev/recovery-procyon/` and `ClientDev/recovery-vineflower/`, not merged into `ClientDev/src/`. The full original CFR recovery remains available in `ClientSRC/`. **None of the alternative sources are considered a working client until a full build and runtime test passes.**

The original `LyMeowz.jar` file is an experimental bytecode reference, **not** a substitute for user-controlled rights to modify/distribute the game's code and resources.

## Bytecode overlay — verified experimental JAR (October 23, 2026)

**The full decompiled source still does not compile.** To unblock incremental
client development, `ClientDev/overlay/` builds a **separate** Java 8 JAR
from the unmodified original `LyMeowz.jar` plus a small source-coded extension.

```bash
bash ClientDev/overlay/build.sh
```

Verified in [GitHub Actions run #39937830850](https://github.com/KhanhLyNek/LyMeowz/actions/runs/39937830850):

- Full build and JAR integrity checks: **PASS**
- Existing 351 original classes: **350 byte-identical**, one modified
  (`main/GameMidlet.class`)
- Added extension: `dev/lymeowz/client/BuildHook.class`
- Total resulting classes: **352**, preserving all original resource bytes
- Injected single call to `BuildHook.announce()` into
  `main.GameMidlet.startApp()`; confirmed by ASM and `javap`
- Output SHA-256: `3a3e89b8c9bd924d3edc17dfc0206829bb57f359bf1c977208dc83e71d6b059c`

**NOT YET TESTED:** Java ME launch, runtime execution, rendering, login,
server compatibility, multiplayer or security. The existing original JAR's
classfile version 52.0 is retained.

This overlay is the recommended **first incremental-development path**, not a
source reconstruction success claim. Full-source recovery efforts remain
separate.

## Safe JVM class loading and overlay runtime smoke tests

[GitHub Actions #39940981442](https://github.com/KhanhLyNek/LyMeowz/actions/runs/39940981442)
**PASS**. The original patched client `GameMidlet` and five representative
network/data classes are linked with initialization disabled. Resources
(manifest and icon) are readable. Our own `BuildHook.announce()` is invoked
from the rebuilt JAR; a separate harmless fixture proves patch entry ordering.

Run `bash ClientDev/overlay/smoke.sh` to reproduce. **No real game
initialization or online session was attempted.** See `overlay/README.md`.
